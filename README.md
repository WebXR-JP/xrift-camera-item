# Cine Drone Camera — 自律飛行する撮影ドローン（XRift アイテム）

その場にいる人を自動で追跡し、**動きと視線を見てカットを切り替えながら**飛び回る撮影ドローンです。
ドローン視点は現場モニタにリアルタイムで映り、ボタンひとつでそのまま `.webm` に録画できます。

```bash
npm install
npm run dev          # http://localhost:5199（ダミー参加者 4 人つきのテストシーン）
npm run build
xrift upload item
```

---

## なにが動いているか

| | |
|---|---|
| **被写体トラッキング** | `useUsers()` の `getMovement()` を毎フレーム読んで、全員の位置・向き・移動速度・ジャンプを追う |
| **注目度** | ならした運動量・ジャンプ・「何人がその人を見ているか」を合成して、今その場の中心にいる人を出す |
| **カット割り** | 10 種類のショット（WS / MS / CU / OTS / ORBIT / CRANE / DOLLY / TRACK / LOW / TOP）から状況に応じて重み付き抽選 |
| **飛行** | 指数補間 + 速度クランプ + 横加速度によるバンク + 手ブレ。ジンバルが機体の傾きを打ち消して被写体を狙い続ける |
| **モニタ** | ドローン視点をオフスクリーンに描いて、2D キャンバスのビューファインダ HUD を重ねて表示 |
| **録画** | レンダーターゲット → 非同期リードバック → 2D キャンバス → `captureStream` → `MediaRecorder` → `.webm`（映像のみ） |

### 撮り方（モード）

| | | |
|---|---|---|
| `AUTO` | おまかせ | 動き・ジャンプ・視線から注目度を出して自動で選ぶ |
| `ACTION` | よく動く人 | ならした運動量がいちばん高い人を追走する（TRK / ORB / LOW だけを使う） |
| `PIN` | 指名 | 選んだ 1 人だけを撮り続ける。その人が抜けたら自動で次の人へ寄せ直す |
| `FOLLOW ME` | 自分 | 自分だけを撮り続ける |
| `ORBIT` | 回り込み | 全員のまわりを回り続ける |
| `PARK` | 停止 | 台座に戻ってホバリング |

`AUTO` 以外は「誰を撮るか」がモードの意味なので、主役はモードが決め切ります。
寄り引きの都合で別の人に画が移るショットは、そのモードの候補から外してあります。

### 操作

操作するところは 2 か所。どちらもデスクトップでも VR でも押せて、押した結果はその場の全員に同期します。

**モニタの下**（撮り方を決めるときに見ているのは台座ではなく画面なので、こちらが主）

- **モードのチップ 7 個** — 押したものが光ります。今どれで撮っているかがひと目で分かります
- **◀ PREV / NEXT ▶** — フォーカスする人を 1 人ずつ送ります。押すとそのまま `PIN` に入ります
- **真ん中の帯** — 今フォーカスしている人の名前と、選ばれた理由と、**その人が今動いているか**（運動量メーター付き）

**台座の 4 つのボタン**（モニタを出さない置き方でも一通り操作できます）

- **MODE** — 面に `いまのモード → 次のモード` と出ます。押す前に何になるか分かります
- **NEXT ▶** — 次の人にフォーカスする（`PIN` に入ります）
- **CUT** — 次のカットへ即座に切り替え
- **REC** — 面の表示が `● REC` / `■ STOP` と入れ替わります。停止すると自分の端末に `.webm` が保存されます（録画はクライアントごと・映像のみ）

台座のステータスにも `モード ▸ 今フォーカスしている人` と運動量メーターが出るので、
モニタを消していても「誰を撮っていて、その人が動いているか」は分かります。

## 音声には触れていません

XRift には「誰が喋っているか」を返す API がありません（`useVoiceVolumeOverride` は音量を
**書く**ための API で、読めるものではありません）。

以前はプラットフォームが鳴らしている音を Web Audio で覗いて話者を推定していましたが、
**やめました**。既存の `THREE.Audio` や `<audio>` を探して `AnalyserNode` を分岐させる
やり方は、読み込み順・ボイス実装・音源とアバターの対応付けに依存し、壊れ方が静かで
原因も追いにくい（＝バグの温床）ためです。

いまは **声を一切使わず**、動き・ジャンプ・視線（何人がその人を見ているか）だけで
主役を決めています。人が集まって注目している人は、たいていその場の中心にいる人なので、
実用上はこれで足ります。

その結果として:

- 録画される `.webm` は**映像のみ**です（音を入れるには音声グラフを覗くか `navigator.mediaDevices` が要ります）
- `AudioContext` も `AnalyserNode` も作らないので、毎フレームの RMS 解析と 1.5 秒ごとの `scene.traverse` が消えました
- 自分を撮らせたいときは **FOLLOW ME**、特定の人を撮りたいときは **PIN** を使ってください

### セキュリティ審査

`@xrift/code-security` の全ルールに対して **critical / warning ともにゼロ**です。`xrift.json` に `permissions` の宣言は要りません（`localStorage`・`fetch`・`eval`・`innerHTML`・`navigator.*`・Web Audio のいずれも使っていません）。

## 全員の画面で同じ絵になる仕組み

ドローンの座標を毎フレーム同期すると通信量が爆発するので、**同期するのはカット割りだけ**です。

```
useInstanceState({ shot, ids, startedAt, duration, seed, mode })   ← カットのたびに 1 回だけ送る
        ↓
各端末が同じ seed から同じ乱数列を作り、同じ式で軌道を計算する
        ↓
全員の画面でドローンが同じところを飛ぶ（座標は 1 バイトも流れない）
```

- 書き込むのは、参加者 ID を並べて先頭の 1 人（**ディレクター役**）だけ。全員が書くと取り合いになります
- ディレクターのタブが裏に回ると `requestAnimationFrame` が止まってカットが進まなくなるので、**3.2 秒沈黙したら他のクライアントが引き継ぎます**（[`DIRECTOR.STALE_TAKEOVER_MS`](src/camera/constants.ts)）
- 時刻は `useServerClock()`。同期が取れていなければ端末時計にフォールバックします

## Props

すべて省略可能です。

| Prop | 既定値 | |
|---|---|---|
| `position` / `rotation` / `scale` | — | 設置トランスフォーム |
| `mode` | `'auto'` | 初期モード |
| `range` | `22` | 設置位置からの最大水平飛行距離（m） |
| `minAltitude` | `0.45` | 床からの最低高度（m） |
| `maxAltitude` | `14` | 設置位置からの最高高度（m） |
| `handheld` | `0.55` | 手ブレの強さ。`0` で完全に滑らか |
| `showMonitor` | `true` | 現場モニタを出すか |
| `monitorWidth` | `1.5` | モニタの横幅（m） |
| `quality` | `'normal'` | 画質プリセット。下の表を参照 |
| `feedWidth` / `feedHeight` | プリセット依存 | 解像度を直接決めたいとき（`quality` より優先。片方だけでも効く） |
| `feedFps` | プリセット依存 | ドローン視点の描画 fps（近くにいるとき。遠いと自動で下がる） |
| `recordFps` | プリセット依存 | 録画 fps |
| `cullDistance` | `32` | これより遠い端末では映像パスを止める |
| `shadows` | `true` | 機体とモニタの影。`false` にするとワールドの影パスから完全に外れる |

### 画質を上げたいとき

既定は軽さ優先の `normal` です。録画をきれいに残したいワールドでは `quality` を上げてください。
ここで決まる解像度は **モニタに映る絵と、録画される `.webm` の両方** の解像度です。

| `quality` | 解像度 | fps | ピクセル数（`normal` 比） |
|---|---|---|---|
| `low` | 256x144 | 15 | 0.44x |
| `normal`（既定） | 384x216 | 20 | 1x |
| `high` | 640x360 | 24 | 2.8x |
| `ultra` | 960x540 | 30 | 6.2x |

```tsx
<Item quality="high" />
<Item feedWidth={1280} feedHeight={720} />   {/* プリセットによらず直接指定 */}
```

オフスクリーンパスのピクセル数がそのまま増えるので、`ultra` は「素材として録りたい」用途向けです。
`quality` を上げても、遠いクライアントで更新頻度が落ちる仕組みと、モニタが画面に入っていない
フレームを飛ばす仕組みはそのまま効きます。

```

  camera/

    useDirector.ts          いつ・誰を・どう撮るか。インスタンス同期とディレクター選出
    useDroneRig.ts          理想の姿勢へ機体を追従させる（バンク・手ブレ・ジンバル）
    useCameraFeed.ts        ドローン視点のオフスクリーン描画
    hud.ts                  ビューファインダ HUD（2D キャンバス）
    useRecorder.ts          リードバック → 合成 → MediaRecorder
    platform.ts             Provider 外でも落ちないよう Context を包む
  parts/
    Drone.tsx               機体の見た目。静的パーツはマテリアルごとに 1 メッシュへ統合
    Monitor.tsx             浮いている現場モニタ + その下の操作 UI
    Dock.tsx                離着陸パッドと台座のボタン
    PanelButton.tsx         押せるボタン 1 個（台座とモニタで共通）
    canvasTexture.ts        ボタンの文字を 1 枚に詰める atlas と、書き換わるステータス表示

  devScene.tsx              開発用テストシーン（ダミー参加者 4 人）
  dev.tsx                   npm run dev のエントリ
  dev-headless.tsx          検証用エントリ（後述）
```

### 描画パスについて

`useFrame` の `priority` は **0 のまま**にしてあります。`priority` を 1 以上にすると R3F の自動描画が止まり、アイテムがワールド全体の描画ループを乗っ取ってしまうためです。オフスクリーンパスは「レンダーターゲットを一時的に差し替えて 1 パス足す」だけで、終わったら元に戻します。

- POV パスの間だけモニタと機体を消します。モニタを消さないと、自分の映像を映しているテクスチャに書き込むことになってフィードバックループになります
- VR 中は `gl.xr.enabled` をこのパスの間だけ切ります。切らないと XR カメラで描かれてしまいます
- **実光源（`PointLight` など）は 1 つも置きません。**飛び回るアイテムが光源を持つと、ワールド側の全マテリアルにライト 1 つ分のコストが乗り、シェーダの再コンパイルも誘発します。タリーランプなど光って見せたい所は emissive のマテリアルだけで作っています
- **モニタが画面に入っていないフレームでは、POV パスを丸ごと飛ばします。** このアイテムでいちばん重いのは「ワールドをもう 1 回描く」ことなので、後ろを向いている間それが止まるのがそのまま効きます（実測: モニタ正面で 1.2 秒あたり 22 パス → 背を向けると 0）。録画中だけは、見ていなくても回します
- 距離に応じて POV パスとビューファインダ HUD の更新頻度を落とします（近くで 20fps / 12fps、`cullDistance` いっぱいで 6fps / 4fps）。録画中は指定どおりの fps を保ちます
- 被写体をビューファインダ座標へ投影する処理も、モニタが見えているフレームだけ走ります
- 機体の静的パーツはマテリアルごとに 1 メッシュへまとめてあります（42 → 14 メッシュ）。三角形は 1500 枚ほどしか無いので、機体のコストはほぼドローコールの数で決まります
- ボタンの文字は 1 枚の atlas に詰めて uv で切り出しています。パネル中のラベルが「1 テクスチャ・1 マテリアル・1 メッシュ」になり、アイテム全体で **マテリアル 31 → 17・テクスチャ 17 → 5・メッシュ 48 → 36** まで落ちました
- 影を落とすのは機体とモニタだけです（操作ボタン 10 個ぶんの影キャスタは外しました）。`shadows={false}` で残りも外れます
- 映像と HUD をプレーン 2 枚に分けているのは、映像は GPU 上のテクスチャをそのまま貼れば実質タダなのに対し、HUD は 2D キャンバスなので 15fps に落としたいからです

## 開発

```bash
npm run dev        # http://localhost:5199
```

ダミー参加者 4 人が歩き回ります（決定論的なので毎回同じ動きで再現します）。台座とモニタのボタンはクリックで押せます。

### `dev-headless.html`（検証用）

`<Canvas>` は ResizeObserver でコンテナを測ってから WebGL を初期化するため、**タブが非表示だと起動しません**。CI や自動検証でフレームを進めたいときのために、R3F の命令型 API でサイズを直接与えて起動するエントリを用意してあります。

```
http://localhost:5199/dev-headless.html?w=1280&h=720
```

コンソール（または自動化スクリプト）から:

```js
__dev.step(60)                 // 60 フレーム進める（frameloop は 'demand'）
__dev.shot('name')             // canvas を PNG にして .dev-shots/name.png へ保存
__dev.state                    // R3F の RootState
```

`POST /__shot` は `vite.config.ts` の dev 専用プラグインです（`apply: 'serve'`）。ビルド成果物には入りません。

## Shared 依存関係

このアイテムは [Module Federation](https://module-federation.io/) を使っており、以下はホスト（xrift-frontend）と共有されます。アイテムのバンドルにはインライン化されません。

| パッケージ | バージョン |
| --- | --- |
| `react` / `react-dom` | ^19.0.0 |
| `three` / `three/addons` | ^0.183.1 |
| `@react-three/fiber` | ^9.3.0 |
| `@react-three/rapier` | ^2.1.0 |
| `@react-three/drei` | ^10.7.3 |
| `@react-three/uikit` / `@pmndrs/uikit` | ^1.0.0 |
| `@xrift/world-components` | ^0.47.0 |

`three/addons` も shared です。`DRACOLoader` や `GLTFLoader` は必ず `three/addons/*` からインポートしてください。インライン化されると `new Worker()` などが `@xrift/code-security` の critical 違反として検出されます。

なお、このアイテムは **3D の文字を含めて外部アセットを一切読み込みません**。drei の `<Text>`（troika）はフォントを CDN から取りに行くため使わず、文字はすべて 2D キャンバスをテクスチャにして貼っています。
